# HIDS - Host Intrusion Detection System

A simple, efficient, and tamper-resistant host-based intrusion detection system written in C. The system monitors file system changes in real-time, checks TCP and UDP sockets, and ensures log integrity through cryptography.

## Key Features

- **Asynchronous Monitoring (epoll + inotify):** Handles thousands of simultaneous events without blocking execution, dynamically allocating memory when necessary.
- **Log Integrity:** Uses a SHA-256 hash chain on the logs. Each log line is hashed together with the previous line's hash. If an attacker modifies a past log, the entire chain breaks, revealing the tampering.
- **Resource Exhaustion (DoS) Protection:** Limits "directory bombs" by monitoring a maximum number of dynamically created folders at runtime, preventing kernel file descriptor exhaustion (default: 100).
- **Secure File Link Detection:** Prevents infinite loops generated by symbolic links during recursive directory scanning.
- **Suspicious Socket Connection Detection:** Detects suspicious TCP and UDP socket connections, notifying in the log file any remote connections made to an address not present in a whitelist file.

## Prerequisites

To compile and run the HIDS, you need to have the GCC compiler and OpenSSL development libraries installed (for log hashing).

For Debian-based systems:
```bash
sudo apt-get update
sudo apt-get install build-essential libssl-dev
```

---

## Compilation

The project consists of separate modules. To compile the executable, use `gcc` including the `pthread` (for multithreading) and `crypto` (for OpenSSL) libraries.

Run the following command in the project directory:

```bash
gcc main.c log.c netscan.c -o ids -lpthread -lcrypto
```

---

## Usage

Once compiled, you can start the HIDS directly. By default, it will monitor critical directories such as `/etc/`, `/tmp/`, `/bin/`, as well as sensitive paths in the user's Home directory (e.g., `.ssh/`, `.bash_history`).

You can also pass additional custom folders to monitor as command-line arguments:

```bash
./ids /your/path/1 /your/path/2
```

Connections will also be monitored through the `/proc/net/tcp` and `/proc/net/udp` files to check active sockets.

You can also pass additional addresses to the whitelists for comparison by adding them to the files:
 
`whitelist_tcp.txt` and `whitelist_udp.txt`

To terminate the program safely (cleaning up memory and closing logs), press `Ctrl+C`.
Logs will be saved in the `integrity.log` file, and connection logs will be saved in `socket.log`.

## Module Structure

### main.c (Core & File Monitoring)
The heart of the system. It initializes `inotify` and `epoll`, handles the initial recursive scan and the addition of dynamic watches. It handles interrupt signals for a clean shutdown (freeing dynamically allocated memory).

### log.c & log.h (Logging)
The module responsible for writing logs. It calculates the concatenated SHA-256 hash (`lasthash`) for each new event detected by the Core module, ensuring the temporal immutability of the logs.

### Communication / Network Module (Socket Monitoring)
The module responsible for monitoring active network connections. It reads the Linux kernel's `/proc/net/tcp` and `/proc/net/udp` files in real-time, extracting and decoding remote addresses in little-endian hexadecimal format. Parsing is applied to convert them, and they are subsequently compared against a whitelist for each of the two types to verify the address; if it is not present, it is reported in the terminal with red text and recorded in the log file.
